# Gully Bridge (testnet)

One bridge app for GullyChain Testnet (485590) and Arbitrum Sepolia (421614), with two lanes:

| Lane | What it uses | Time | You get |
|---|---|---|---|
| **Fast** | Hyperlane warp routes (our validator and relayer) | about a minute, both ways | gETH ("Gully Bridged ETH") on GullyChain, ETH back on Arbitrum Sepolia |
| **Canonical** | GullyChain's Arbitrum Nitro rollup bridge (Inbox, ArbSys, Outbox) | deposits about a minute; withdrawals take the challenge period, then a claim | native gas ETH |

The app suggests a lane for each amount and direction (`src/bridge/selectRoute.ts`, unit-tested), and the user can switch.
It is to replace the canonical-only bridge at testnet-bridge.gullychain.xyz.

## Why a separate app in this fork

Since v3 ("Engine-Owned Transfers"), the upstream template sends every transfer through Hyperlane's hosted Universal
Router API. That API does not know chain 485590 or our routes, and the template needs a Next server. This folder is a
static Vite + React + viem app that calls the warp routers and the rollup bridge directly. It shares no code with the
template, and the template stays untouched for future upstream merges.

## Layout

| Path | What |
|---|---|
| `src/config/routes.json` | Fast routes, generated by `npm run routes -- <gully-ops>/l3/hyperlane/registry` from the registry's `deployments/warp_routes/*/*-config.yaml`. The default is the route whose GullyChain token is `gETH`; hypETH stays listed. |
| `src/config/chains.ts` | chains, mailboxes, Nitro bridge addresses (from gully-labs/arbitrum-token-bridge `orbitChainsData.json`), links |
| `src/bridge/bridgeClient.ts` | **the seam**: the UI only calls `getBridgeClient()`. `@gullylabs/bridge-sdk` (GullyBridgeRouter, integrator fees) plugs in with `setBridgeClient()`. |
| `src/bridge/localClient.ts` | built-in client: quotes (`quoteTransferRemote`), sends, tracking (Hyperlane `Mailbox.delivered`, the computed deposit tx id, the outbox leaf), claims (`constructOutboxProof` + `Outbox.executeTransaction`, BoLD rollup) |
| `src/bridge/stats.ts` | live analytics from chain events only. Arbitrum Sepolia's public RPC allows only 100k blocks per `eth_getLogs` when a filter position has several values, so those queries go out in 90k-block windows. |
| `src/ui/c/AppC.tsx` | **the shipped design** (owner pick, "C · Hybrid"). `src/ui/a` and `src/ui/b` are the two earlier directions, kept for the picker. |
| `deploy/Caddyfile.bridge` | Caddy block for gully-l3 (static files, SPA fallback, CSP, rollback to the old container). `connect-src` allows every GullyChain RPC of the fallback list, `gullychain.xyz` (ETH/USD off a gullychain host) and `api.redstone.finance`. |
| `src/gc-switcher/` | the GullyChain product switcher, a byte-identical copy of gully-ops `sites/_shared/gc-switcher` (spec in its README). Do not edit it here. |
| `src/config/rpc.ts`, `src/bridge/clients.ts` | GullyChain RPC fallback: viem `fallback()` (rank off, 8 s per URL) over same-origin `/rpc` (on a gullychain.xyz host), `rpc.gullychain.xyz`, `rpc.gullyrpc.xyz/gullychain/evm/485590`, `rpc2.gullychain.xyz`, `testnet-rpc.gullychain.xyz`. `VITE_GULLY_RPC` (comma-separated) goes in front. Wallets get rpc.gullychain.xyz, rpc.gullyrpc.xyz, testnet-rpc (rpc2 once its DNS exists). |
| `src/bridge/usd.ts`, `src/ui/common/money.tsx` | USD first, ETH second: Gully's `/price/eth` (same-origin, else gullychain.xyz), then the RedStone API, then GullyPriceFeed on chain through the RPC fallback; no CoinGecko from the browser. Cached 60 s. With no price, amounts show in ETH only. |

## Integrators

- `?ref=0x…`: the integrator address. It is kept for the session, shown on the quote and passed as `req.ref` to the bridge client.
- `?embed=1` or `/embed`: the card only, transparent background. It posts `{type:'gully-bridge', event:{type:'ready'}}` to the parent window.
- Other query parameters: `direction=deposit|withdraw`, `route=fast|canonical`, `amount=0.01`.

## Sign in with Gully (feature flag, off by default)

`VITE_GULLY_ID_CLIENT_ID=gully-bridge` at build time adds a "Sign in with Gully" button to the header
(`src/gully-id/`). It lazily loads `https://id.gullychain.xyz/sdk.js` (override with `VITE_GULLY_ID_ISSUER`) and shows
the user's .gully name and avatar, plus their Gully ID wallet address when the profile has one. It is identity only:
transfers are still signed by the wallet connected with Connect, and nothing is auto-connected. Unset = no button and
the SDK is never requested; if the SDK fails to load the button simply does not appear. Needs the CSP in
`deploy/Caddyfile.bridge` (id.gullychain.xyz in script-src and connect-src, https: in img-src).

```sh
VITE_GULLY_ID_CLIENT_ID=gully-bridge node scripts/build-staging.mjs <out>
```

## Commands

```sh
npm install
npm run brand            # copy the GullyChain kit v3 + Gully Labs badge into public/ (byte for byte)
npm run routes -- ../../gully-ops/l3/hyperlane/registry
npm run dev              # VITE_DIRECTION=a|b|c; GullyChain RPC is proxied to the SSH tunnel (127.0.0.1:18545)
npm test                 # unit tests
node tests/simulate.mjs  # every transfer path as eth_call against the live contracts, from a throwaway address
BASE=http://127.0.0.1:5234/ CHROME=<chrome.exe> node tests/e2e.mjs   # Playwright 375/768/1280/1920
node scripts/build-staging.mjs <out>   # production static build (direction C, production RPCs)
```

Deploy: `sh scripts/deploy-l3.sh <stagedDir>` uploads to `/srv/status/sites/testnet-bridge.gullychain.xyz.new` on
gully-l3, copies the live `assets/` into it without overwriting (`cp -rn`, so open tabs keep finding their old lazy
chunks), swaps live -> `.old` and `.new` -> live, then checks the page and every JS chunk on both hostnames. The Caddy
block (`deploy/Caddyfile.bridge`) lives in `gully-ops/l3/edge/Caddyfile.l3.tpl`.

## Notes

- Canonical withdrawals can only be claimed after the rollup confirms an assertion that includes them. As of
  2026-10-26 `latestConfirmed()` is still the genesis assertion, so the UI shows "Waiting for the first confirmed
  rollup assertion" until the BoLD validator posts and confirms one.
- Canonical deposit delivery times are not plotted: the GullyChain block that reads a deposit carries the deposit's
  own timestamp, so the chain cannot measure the delay.
- Attribution: the footer says "Fast lane secured by Hyperlane". The Hyperlane contracts and agents are Apache-2.0;
  this app has no Hyperlane UI code.
